# STEPWISE

STEPWISE — веб-приложение с интерактивными инструкциями. Пользователь выбирает маршрут, проходит его по шагам и отмечает выполнение. Автор может публиковать и редактировать инструкции, а события прохождения попадают в аналитику.

## Запуск

Нужен Node.js 22.13 или новее. Зависимости устанавливать не требуется.

```powershell
npm start
```

Откройте адрес, который появится в терминале: `http://localhost:4173`.

Для остановки сервера нажмите `Ctrl+C` в терминале.

## Что уже работает

- Каталог с поиском по названию и описанию и фильтром по категориям.
- Четыре примера из тем олимпиады: сборка ПК, установка Docker, отчёт по лабораторной и справка в деканате.
- Интерактивное прохождение: список шагов, прогресс, отметка выполненного шага, советы и возврат к предыдущим шагам.
- Создание и редактирование инструкций с материалами, временем, сложностью, ожидаемым результатом и любым количеством шагов от двух.
- Загрузка фотографии-обложки и отдельных изображений для шагов (JPG, PNG или WebP, до 5 МБ).
- Профиль автора с именем для подписей к публикациям.
- Аналитика запусков, завершений и посещённых шагов. Показатели рассчитываются по записанным событиям; демонстрационные числа не подставляются.
- AI-черновик через AnyModel: функция включится после добавления локального API-ключа.
- Адаптивный интерфейс для настольных экранов и телефонов.

## Хранение данных и границы текущей версии

Сервер сохраняет инструкции, шаги, профиль автора и события прохождения в SQLite: `data/stepwise.sqlite`. При первом запуске он переносит существующие данные из `data/store.json` и создаёт резервную копию `data/store.before-sqlite-*.json`. Если JSON отсутствует, используются демонстрационные данные из `data/seed.json`. После переноса JSON больше не обновляется.

Фотографии находятся в `data/uploads/`, в базе хранятся ссылки на них. Незавершённое прохождение сохраняется отдельно в localStorage браузера: на другом компьютере этот прогресс не появится.

Это рабочая локальная версия для разработки и демонстрации. Добавлены регистрация по имени, почте и паролю, вход и выход. Каждый аккаунт имеет отдельный профиль, свои инструкции и статистику. Каталог опубликованных инструкций общий. Аккаунты доступны на том сервере, где были созданы: независимые копии проекта на разных компьютерах не синхронизируются. Для общего сайта в интернете нужны размещение сервера, авторизация и резервное копирование. Текущая версия рассчитана на один процесс сервера.

## Подключение ИИ позже

В проект уже встроен маршрут `POST /api/ai/draft`, который вызывает AnyModel, используя совместимый с OpenAI адрес `https://anymodel.org/v1` и модель `cx/gpt-6-luna`. Интерфейс показывает результат как черновик: автор может исправить его и добавит фотографии до публикации. Без ключа экран честно сообщает, что ИИ не настроен.

Чтобы включить ИИ, скопируйте `.env.example` в `.env`, вставьте свежий API-ключ AnyModel в `ANYMODEL_API_KEY` и перезапустите `npm start`. Не отправляйте ключ в чат, исходный код или Git-репозиторий. Файл `.env` уже исключён из Git.

Текущие API маршруты находятся в `server.js`; интерфейс и работа с ними — в `src/app.js`. Хранилище SQLite подключено через `src/storage.js`; адреса API (`/api/guides`, `/api/events`, `/api/profile`) сохранены.

## Основные файлы

- `index.html` — HTML-точка входа.
- `styles.css` — визуальная система и адаптивная вёрстка.
- `src/app.js` — экраны каталога, прохождения, кабинета автора и аналитики.
- `server.js` — локальный веб-сервер, API и сохранение данных.
- `src/storage.js` — создание таблиц, перенос JSON и транзакции SQLite.
- `data/stepwise.sqlite` — рабочая база данных, создаётся при запуске.
- `tests/integration.test.js` — автоматическая проверка API и хранения данных.


## Как объяснить проект преподавателю

HTML задаёт основу страницы: заголовки, поля, кнопки и контейнеры. В нашем проекте точка входа — index.html, а содержимое экранов также создаёт JavaScript.

CSS отвечает за внешний вид: цвета, шрифты, расположение элементов и адаптацию к телефону. Файлы styles*.css содержат оформление STEPWISE.

JavaScript делает страницы интерактивными: переключает экраны, отправляет инструкцию на сохранение, показывает шаги и прогресс. Основной код интерфейса находится в src/app.js.

Node.js запускает JavaScript вне браузера. В STEPWISE он выполняет server.js — серверную часть приложения. Сервер здесь — программа на компьютере: она ждёт запросов браузера, возвращает страницы, работает с базой и обращается к ИИ. Пока сервер работает на вашем компьютере, адрес localhost открывает сайт на этом же компьютере.

SQL — язык обращения к таблицам базы данных. SQLite — сама система хранения, которая выполняет SQL и записывает данные в файл. У SQLite не нужно отдельно устанавливать сервер базы данных.

Путь сохранения: пользователь нажимает «Опубликовать» → JavaScript отправляет запрос /api/guides → Node.js проверяет инструкцию → SQLite сохраняет её → браузер получает ответ.

## Таблицы базы и SQL

- guides: идентификатор инструкции, порядок в каталоге, поля инструкции.
- steps: ссылка на инструкцию, номер и содержимое шага.
- profile: старый профиль до регистрации (для сохранения совместимости).
- events: события прохождения со ссылкой на инструкцию.
- metadata: отметка завершённого начального переноса.

Тексты и дополнительные поля хранятся в JSON-колонке data внутри таблиц SQLite. Инструкции, шаги и события имеют отдельные строки и связи. Это позволяет сохранить существующий формат приложения. Например:

```sql
SELECT id, json_extract(data, '$.title') AS title FROM guides ORDER BY position;
SELECT guide_id, COUNT(*) AS events_count FROM events GROUP BY guide_id;
SELECT position, json_extract(data, '$.title') AS title FROM steps WHERE guide_id = 'build-pc' ORDER BY position;
```

Сохранение выполняется транзакцией: SQLite записывает согласованный набор изменений целиком или отменяет его при ошибке. Сейчас сервер держит рабочие данные в памяти и записывает весь набор при изменениях. Для небольшой демонстрации это подходит; для большого сервиса нужны выборочные запросы и отдельная система учётных записей.

## Проверка и резервная копия

Запустите `npm test`. Проверка использует временную папку и отдельный порт, не меняет ваши инструкции и не вызывает платный ИИ. Она проверяет перенос JSON, публикацию, профиль, события, фото, некорректные запросы, закрытие служебных файлов и сохранность после перезапуска.

Перед резервным копированием остановите сервер и скопируйте всю папку data: база и загруженные фотографии должны передаваться вместе. Не удаляйте старый store.json до проверки переноса. При работе на Node.js 22 возможно сообщение ExperimentalWarning о SQLite; оно не означает падение сервера.

## Передача и Git

Git хранит версии исходного кода локально. GitHub — сервис, куда можно загрузить Git-репозиторий и дать ссылку преподавателю. Для GitHub нужен аккаунт и адрес репозитория.

В Git включены исходники, тесты, демонстрационные данные и описание запуска. Ключ .env, рабочая база, личные загрузки, отладочные папки и старые ZIP исключены через .gitignore. Для работы ИИ на другом компьютере нужно отдельно создать .env по образцу .env.example.

Для запуска после скачивания: установить Node.js 22.13 или новее, распаковать проект, открыть терминал в папке проекта и выполнить `npm start`, затем открыть http://localhost:4173. Без ключа сайт работает, генерация ИИ потребует настройки. Отдельная установка пакетов не требуется.


## Регистрация и аккаунты

Нажмите аватар или «Новая инструкция»: гостю откроется вход с переключением на регистрацию. Укажите имя, почту и пароль от 8 символов. Для демонстрации используйте отдельный пароль. Подтверждение почты и восстановление пароля пока не реализованы; имя менять можно, почта входа пока неизменна.

В таблице users хранятся аккаунты. Пароли сохраняются как scrypt-хеш с индивидуальной случайной солью, открытых паролей в базе нет. Таблица sessions хранит хеши случайных токенов входа со сроком 7 дней. Браузер получает HttpOnly cookie; выход отзывает сессию. Добавлены ограничение попыток входа и проверка Origin для запросов изменения данных. При размещении в интернете обязательно HTTPS; текущая версия предназначена для локальной демонстрации.

Инструкции привязаны к authorId. Сервер запрещает другому пользователю менять их; статистика выдаётся только автору соответствующих инструкций. Гость может читать каталог и проходить инструкции. Создание, загрузка фото, изменение профиля и генерация ИИ требуют входа. Пользователи одного браузерного профиля делят текущую сессию: для двух одновременных аккаунтов используйте разные браузеры или приватное окно.

Ранее созданные инструкции без authorId остаются в общем каталоге без личного владельца. Они не присваиваются первому зарегистрированному пользователю. Для демонстрации личного кабинета создайте новую инструкцию после регистрации.


## Наполнение каталога

В data/catalog.json добавлены 12 редакционных инструкций — по две на каждую из шести основных категорий, по пять шагов. При запуске сервер добавляет отсутствующие инструкции по ID, не заменяя существующие публикации и не создавая события просмотров. Их автор — «Редакция STEPWISE», личный владелец не назначен. Тематические фотообложки загружаются с Unsplash и требуют интернета.


## Поиск и иллюстрации

Поиск работает локально для всех инструкций, включая пользовательские: название, описание, категория, результат, материалы и шаги. src/search.js содержит нормализацию регистра и ё/е, группы распространённых русских и английских названий и синонимов, поиск по началу слова, приближённое совпадение и проверку английской раскладки вместо русской. Название имеет больший вес, чем текст шагов. Все значимые слова запроса должны совпасть. Это эвристический поиск: он не понимает любой произвольный смысл, словарь можно расширять. Платный ИИ не нужен.

В каталоге 18 редакционных инструкций, по три в шести основных категориях. 18 локальных тематических фотографий используются повторно в обложках и шагах. Фото — иллюстрации темы, а не точные снимки действий. При первом запуске новой версии изображения добавляются также к шагам существующих инструкций без фото; загруженные изображения сохраняются. Последующие изменения пользователей не перезаписываются этим переносом. Скрипт scripts/catalog-images.mjs повторно загружает изображения только при ручном запуске.


## Посмотреть содержимое SQLite

Откройте VIEW-DATABASE.cmd двойным щелчком. Он создаст и откроет локальную HTML-страницу с инструкциями, шагами, аккаунтами и последними 500 событиями. База открывается только для чтения, пароли и токены не выводятся. После изменений на сайте запустите файл повторно. Снимок может содержать имена и почту, поэтому output/database-view.html исключён из Git.
